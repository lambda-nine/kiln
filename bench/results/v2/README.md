# Benchmark v2 results

The published campaign is in
[`macbook-air-2026-10-11/`](macbook-air-2026-10-11/). It contains raw JSONL,
the exact config copied into each run, machine-readable manifests and generated
JSON/Markdown summaries. `docs/benchmarks.md` is the interpretation; these
files are the evidence behind it.

## Layout

- `boot-01-latency` through `boot-05-latency`: randomized lifecycle latency
  at a 100 ms gap on five distinct VM boots.
- `gap-sweep`: 0, 10, 100, 1000 and 5000 ms gaps on one fresh boot.
- `concurrency`: levels 1, 4, 16, 32 and 64, three batches each.
- `memory`: counts 0, 10, 25, 50 and 100, three randomized fits.
- `workloads`: shell, Python, Node, filesystem, DNS and HTTP, each in three
  fresh-boot sessions.
- `podman-net-corrected`: a paired kiln/Podman rerun after assigning Podman a
  non-overlapping bridge subnet. Its first concurrency attempt is retained
  under `invalid-concurrency-*-veth-race`; `concurrency/` is the clean rerun
  after the race fix.
- `*-summary`: generated by `bench/v2.py summarize`; raw records remain the
  source of truth.
- `host.json`: a privacy-filtered macOS host and Lima VM description.
- `validity.json`: machine-readable exclusions and interpretation boundaries.

## Important exclusions

Podman's original default bridge (`10.88.0.0/16`) overlapped kiln's bridge.
The `podman-crun-net` rows embedded in the original all-runtime latency, gap,
concurrency and memory runs are therefore retained as raw history but excluded
from every claim. Use `podman-net-corrected/` for that case.

youki completed the serial latency and memory campaigns, but timed out 22
commands at concurrency levels 4–64. Its concurrency throughput rows are not a
valid comparison. The raw failures are intentionally preserved.

The corrected Podman campaign's first concurrency attempt found one real kiln
failure: a prior sandbox's namespace teardown removed a reused veth between an
`EEXIST` response and kiln's explicit stale-link deletion. The failed run is
preserved under `podman-net-corrected/invalid-concurrency-veth-race/` and is
excluded from performance claims. Commit `2cca44a` treats only the resulting
`ENODEV` as already-cleaned state, adds a 160-start regression, and the standard
`podman-net-corrected/concurrency/` directory is its fresh-boot replacement.

DNS and HTTP contact `example.com`; they include public resolver, route and
server variance. runsc is a stronger-isolation tier. Firecracker and Kata were
not run because this Lima VM had no `/dev/kvm`.

## Regeneration

From the repository root:

```sh
python3 -I bench/v2.py summarize \
  bench/results/v2/macbook-air-2026-10-11/boot-*-latency \
  --out /tmp/kiln-latency-summary --baseline kiln-none \
  --bootstrap-seed 20261011

cd docs/whitepaper
python3 -I gen-data.py ../../bench/results data \
  ../../bench/results/v2/macbook-air-2026-10-11
tectonic kiln-whitepaper.tex
```

See [`bench/README.md`](../../README.md) for the record schema, timing boundary,
schedule, resume rules and complete rerun commands.
